## 1. 导读

React 官方文档中提到的“要保持组件纯粹”主要指的是：**React 的渲染过程必须自始至终是纯粹的**。而非严格意义上的“纯函数”—— **相同输入必须输出相同的 UI**。

组件应该只 **返回** 它们的 JSX，而不 **改变** 在渲染前，就已存在的任何对象或变量 — 这将会使它们变得不纯粹！

## 2. 纯函数：组件作为公式 

在计算机科学中（尤其是函数式编程的世界中），[纯函数][2] 通常具有如下特征：

- **只负责自己的任务**。它不会更改在该函数调用前就已存在的对象或变量。
- **输入相同，则输出相同**。给定相同的输入，纯函数应总是返回相同的结果。

React 便围绕着这个概念进行设计。**React 假设你编写的所有组件都是纯函数**。也就是说，对于相同的输入，你所编写的 React 组件必须总是返回相同的 JSX。

## 3. 【AI】react 中的组件是纯函数？

不完全是。更准确地说：

**React 组件在“渲染阶段”应该表现得像纯函数，但组件整体不一定是数学意义上的纯函数。**

### 3.1. 纯函数的定义

纯函数通常满足：

- 相同输入，永远返回相同输出；
- 不产生副作用，比如不修改外部变量、不发请求、不写 DOM、不修改参数。

### 3.2. 函数组件看起来像纯函数

函数组件形式上是：

```jsx
function Welcome({ name }) {
  return <h1>Hello, {name}</h1>;
}
```

给定相同 `props`，通常返回相同 JSX，这很像纯函数。

但真实组件还可能依赖：

- `state`
- `context`
- `useRef`
- 外部模块变量
- 环境等

所以它的“输入”不只是 `props`，输出也不只是普通值，而是 React 元素描述。因此它不是严格数学意义上的纯函数。

### 3.3. React 要求的是“渲染要纯”

React 官方强调的是：**组件在渲染过程中必须是纯的**。也就是：

- 不要修改传入的 `props`；
- 不要修改外部变量；
- 不要在渲染中发请求、操作 DOM、写 localStorage；
- 不要依赖 `Math.random()`、`Date.now()` 等不稳定值产生渲染结果；
- 不要直接修改 `state`。

例如这是不纯的：

```jsx
let count = 0;

function Bad() {
  count++; // 渲染时修改外部变量：不纯
  return <div>{count}</div>;
}
```

应该把副作用放到事件处理或 `useEffect` 中：

```jsx
function Good() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    document.title = `count: ${count}`;
  }, [count]);

  return <button onClick={() => setCount(c => c + 1)}>{count}</button>;
}
```

### 3.4. 类组件也一样

类组件的 `render()` 方法也应保持纯：根据 `props` 和 `state` 计算 UI，不在 `render` 中产生副作用。

### 3.5. 严格模式会帮助发现不纯

**开发环境下，React Strict Mode 可能会故意双调用组件函数、初始化函数等，帮助发现渲染阶段的不纯行为**。

### 3.6. 总结

- **函数组件不等于纯函数**；
- **React 要求组件的渲染逻辑尽量纯**；
- **组件可以有状态和副作用，但副作用应放在事件处理、`useEffect` 等非渲染阶段**；
- 可以理解为：**组件是一个由 React 管理的、渲染阶段应保持纯的函数式 UI 单元**。
