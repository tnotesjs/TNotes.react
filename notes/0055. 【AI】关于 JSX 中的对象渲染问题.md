## 1. 【AI】plain object 会抛出错误

---

问题：

你能解释为什么 React 中不能直接渲染对象吗？

准确来说，这句话是不是本身就是错误的，因为数组也是 object 类型，通过 typeof 检查的时候返回的也是 object，因此也有说法说数组也是对象，但是数组在 jsx 中我记得又是可以正常渲染的。

---

你的质疑是对的：**“不能直接渲染对象”在口语里常这么说，但严格来说不准确。** 更准确的说法是：不能把 **普通对象（plain object）** 当作 React 子节点渲染。

### 1.1. React 实际怎么判断

协调子节点时，大致是：

1. `string` / `number` / `bigint` → 文本
2. `null` / `undefined` / `boolean` → 不渲染
3. `typeof === 'object' && !== null` 时再细分：
    - React 元素（带 `$$typeof`）→ 正常组件/DOM
    - **数组 / 可迭代对象** → 当成一组 children 展开
    - Promise、Context 等少数特殊类型 → 按约定处理
    - **其余对象** → 抛 `Objects are not valid as a React child`

源码里就是先认元素，再认数组/iterable，认不出来才报错：

```ts {20} [react 源码片段]
// packages/react-reconciler/src/ReactChildFiber.js
    if (typeof newChild === 'object' && newChild !== null) {
      switch (newChild.$$typeof) {
        case REACT_ELEMENT_TYPE: {
          // ...
        }
        // ...
      }

      if (
        isArray(newChild) ||
        getIteratorFn(newChild) ||
        // ...
      ) {
        // 数组 → Fragment / 一组子节点
        // ...
        return created;
      }
      // ...
      throwOnInvalidObjectType(returnFiber, newChild);
    }
```

所以：`typeof` **都是 **`'object'`** 并不妨碍数组能渲染** ——React 用的是 `Array.isArray` / iterator，不是 `typeof`。

### 1.2. 为什么禁止 plain object

- 没法可靠决定怎么显示：`{a:1}` 该显示什么？JSON？某个字段？还是忽略？
- 和「合法子节点」撞型：元素、Portal 等也是 object，只能靠约定形状（如 `$$typeof`）区分；随便一个 `{name: 'Ada'}` 没有这套约定。
- 报错文案也会提示：若你本意是一堆子节点，请用**数组**。

### 1.3. 对照

| 值 | `typeof` | 能否作为 JSX 子节点 |
| --- | --- | --- |
| `'hi'` / `42` | string/number | 可以 |
| `{ name: 'Ada' }` | object | **不可以** |
| `['a', <b/>]` | object | **可以**（展开成多个子节点） |
| `<div />`（元素） | object | 可以 |


- **plain object** 才是准确表述（比如上表中的 `{ name: 'Ada' }`）
- 口语里的「不能渲染对象」其实是在说「不能渲染 plain object」
